# METH-186/187: stored grouped-Q6 core with quality-valid E1280 bank

**Uncertainty and prior evidence.** The centered BF16 Qwen2.5-0.5B-
Instruct E1280 bank passes METH-121/123 external quality and METH-183
shows that its learned child route matters. The full native FP32 core
plus this bank is too slow. Grouped-Q4 FFN damages model quality
severely; grouped-R8 FFN has better automatic quality but fails blind
grounding and the measured C component budget. A grouped signed-Q6
FFN, BF16 attention and stored R8 head would leave substantially more
active-byte room than grouped-R8 for a later trained correction while
changing the complete core together with the validated expert bank.
The question is whether that specific stored representation merits
joint correction training or an independent quality audit.

**METH-186 stored representation.** Bind the pinned Qwen2.5-0.5B-
Instruct revision `7ae557604adf67be50417f59c2c2f167def9a775`,
source SHA-256
`fdf756fa7fcbe7404d5c60e26bff1a0c8b8aa1f72ced49e7dd0210fe288fb7fe`,
and METH-85 grouped-R8 core SHA-256
`c484a1130e495342d1b8644ff156cc002d0fd68fe12230604e59f35d3af6433a`.
Reuse its exact R8 tied-head codes/scales, BF16 attention and FP32
controls. For each of 72 donor BF16 gate/up/down FFN matrices,
partition each output row into consecutive 64-weight input groups.
Store one FP16 scale `max(abs(group))/31`, or one for an all-zero
group, and round/clamp signed int6 codes to `[-31,31]` against the
stored scale. Map code `q` to unsigned `q+32`; pack four 6-bit codes
into three bytes, lowest input index in least significant bits.
Reconstruct as signed code times stored FP16 scale rounded to BF16.
Check all tensor shapes, complete physical reload, every reconstructed
FFN matrix and source/head/control identity. Expected core payload is
470,254,592 bytes, exactly 78,446,592 below METH-85's group-R8
payload. Require the ideal addressed core plus the E1280 parent/child
router and four selected shared-A/B factors to stay ≤560,000,000
bytes/token; report the route and factor terms separately. Physical
file bytes and resident bank bytes are separate, not DRAM claims.

**METH-187 development composition.** On the already consumed METH-121
24 code/prose/technical documents and chat prompts, load the exact
METH-107 child checkpoint, METH-56 parent and mean-center every
ten-child B around its parent as METH-122 did. First reproduce its
24 BF16 E1280 document nats exactly and donor-top-1 match counts.
Then replace only the core head and FFN with reconstructed tensors
from the stored METH-186 artifact and score the same documents and
prompts with experts disabled and enabled. Report all four arms:
BF16 donor, BF16+E1280, Q6 donor and Q6+E1280. Frozen
continuation gates for the Q6+E1280 arm: pooled BPB at most 0.01
worse than BF16+E1280; each category at most 0.02 worse; pooled
donor-top-1 agreement at most one percentage point below BF16+E1280;
and each category at most two points below. Record every row and all
categories even if gates fail. If the stored representation fails,
the next candidate must add a separately specified trained correction
within the byte margin rather than repeat this exact quantizer. If it
passes, freeze a new source-disjoint generation/task/blind-grounding
audit before any native promotion. These viewed-source scores cannot
overturn an earlier semantic failure or prove quality themselves.

**Resource and stop.** Local RTX 3060 only, six CPU threads. Export:
15 minutes, 10.5 GiB peak allocated GPU memory, 20 GiB RSS and 1 GB
new disk. Composition: 15 minutes, same memory limits, <1 GB new
small results. Stop on a hash/readback, BF16 baseline-parity,
nonfinite-output, size or resource failure; preserve stage and partial
rows. No T4. This experiment does not measure C route/LUT cost,
native full-model accepted-token rate or transfer to 10B/100B.
