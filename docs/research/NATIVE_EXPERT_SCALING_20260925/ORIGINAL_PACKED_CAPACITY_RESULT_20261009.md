## What was implemented

E4BPv001 uses runtime n/V,64-bit byte extents/offsets,110 named typed field
descriptors, byte-pair ternary codes, F32 row scales and sensitive organs.
It validates dimensions, exact extent/field coverage, multiplication overflow,
unique names, finite organs, positive scales and legal codes. Original D256/L6,
five SSM/Mamba1-like blocks plus one SWA, N96/DN512/H128/k8 are the fixed core
geometry of this first version. Original dReLU/AQ63/fast-exp arithmetic is retained.
Dense/F32-expert/shortlist modes are unsupported in this ABI.

20 complete function bodies are extracted from actual phase60/engine.c.19 are
unchanged; mlp_moe adds only memcpy of its actual selected IDs/masses. Removing
that observer recovers its exact original source. Individual body/header hashes
are in the result and off-repo original_bodies.json. The adapter contains original
computations with a new loader/typed prefix interface; original phase60/engine.c
bytes are unchanged. It is a separate backend entry, not a generic donor runtime
or a new admitted chatbot interface. Persistent canonical chat wiring is still
a later integration step for a useful learned artifact.

The loader retains one packed blob plus explicit state/router/logits workspace.
Original A_log is transformed in that blob with the original -expf; immutable
disk input remains unchanged. No dequantized F32 expert or unpacked int8 expert
tensor is allocated. The exporter streams one converted field at a time. Its
validated producer currently parses the actual legacy E32 format; a direct
producer from new source-informed learner tensors is still missing.
