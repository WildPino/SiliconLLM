# METH-96: specialize the function-preserving E1280 children

Start from the bitwise-identical METH-95 expansion of the quality-audited METH-56 E128 checkpoint. Freeze the BF16 donor, all dense weights, parent product-key router, child projection/keys and child A factors. Update only the 1,280 child B factors in each layer. This is a test of whether the expanded slots can become distinct without losing the E128 teacher's behavior; it does not establish useful additional model capacity or CPU performance.

Use the pinned H0 raw training IDs and METH-43 chat training rows, excluding all METH-56 training-development row IDs from raw draws. Sample with NumPy seed 96096 for 128 updates, one 128-token raw draw and one chat draw per update. For each draw, the teacher is BF16 donor plus the frozen METH-56 E128 bank. Train the expanded student with CE against observed next tokens plus teacher KL, weight 2 for raw and 4 for chat. Chat CE covers assistant continuation targets; chat KL covers all positions. AdamW learning rate 1e-4, zero weight decay, global clip 1.0. No load-balancing gradient. Save exact draw IDs and checkpoint.

Stop on nonfinite loss/gradients, >15 minutes, >10.5 GiB GPU peak allocation, or >20 GiB process RSS. Local RTX 3060 only; no T4. Report initial and final child-factor changes relative to each copied parent, changed-slot count per layer (max absolute B difference >1e-7), and the fraction of each layer's ten child slots reached by training routes. Require at least 640 changed slots per layer for this specialization pilot; otherwise it fails the distinct-slot gate. Do not infer quality from training loss.

Development will use a separately frozen, source-disjoint 24-document manifest. Compare BF16 donor, BF16+original E128 teacher, and BF16+specialized E1280 on identical documents and prompts. Gates: E1280 pooled BPB no more than +0.01 above E128, each category no more than +0.02 above E128, pooled prompt top-1 no more than one percentage point below E128, each category no more than two points below E128, and at least 640 changed slots per layer. A development pass permits a separate external automatic and blind-semantic audit; it does not promote a native full model. CPU LUT cost, resident RAM, cold DRAM behavior, and end-to-end `engine.c` remain separate gates.
