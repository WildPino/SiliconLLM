# METH-195/196: lower FFN weight MSE worsens prompt ranking

The [protocol](METH_195_196_Q8_MSE_SCALE_PROTOCOL_20260930.md),
[exporter](../../../benchmarks/donor_adaptation/s1/meth195_export_group64_q8_mse_core.py)
and [scorer](../../../benchmarks/native_expert_scaling/meth196_q8_mse_core_e1280_development.py)
were committed at `dc84f2a` before execution. Exactly three
least-squares scale/code rounds were applied per 64-weight FFN group;
each group retained its METH-193 max-scale form if that had lower
BF16-reconstruction weight MSE. All 363 stored tensors and 72 FFN
BF16 reconstructions matched byte for byte after reload. Maximum
FFN relative weight L2 dropped from 0.7114% to **0.6967%**.

The stored artifact at
`results/native_expert_scaling/meth195_qwen05b_instruct_group64_q8_mse_core.safetensors`
is 548,741,408 physical bytes, SHA-256
`084fb65c420af1d19a3531316eea32ba098356d08440a4a4e4e5304201097fd5`.
The [export ledger](meth195_group64_q8_mse_core_export.json), SHA-256
`aee53a509d86b5e8786915957c2eb79394a6c9653b361ea0d93e288c25b942f3`,
confirms the same **559,981,568 ideal addressed bytes/token** as
METH-193. The different physical header size is not a per-token
weight read.

METH-196 exactly reproduced METH-187's BF16 donor and BF16+E1280
per-source NLL and prompt match counts before scoring the new core on
the same already viewed METH-121 sources.

| Same 24-source measure | BF16+E1280 | Q8 max-scale METH-194 | Q8 MSE METH-196 |
|---|---:|---:|---:|
| Pooled BPB | 1.184887 | 1.184919 | 1.185037 |
| Donor prompt top-1 | 94.504% | 93.391% | 92.879% |
| Code prompt top-1 | 92.817% | 90.588% | 90.402% |

Both BPB gates pass, but pooled top-1 loses 1.624 points against the
allowed one and code loses 2.415 points against the allowed two.
**Both ranking gates fail, more clearly than METH-194.** The
[raw result](meth196_q8_mse_core_e1280_development_result.json),
SHA-256 `07afb85ba42b31dbc3ada7f10b7898a00e41c75a2468bc5ec24506a80851306f`,
contains every source/category value and four-arm comparison.
Export took 12.312 s with 154.0 MB peak GPU allocation; scoring
took 46.157 s with 4.270 GB peak GPU allocation. No T4 or fresh
source was used.

The lower weight MSE did not predict donor ranking retention. Stop
this Q8 scale-refinement route; neither Q8 artifact passed the fixed
development gates, so neither advances to fresh quality or full
native C rate. The Q8 format also has only an 18,432-byte ideal
margin before additional selected-router costs from a larger n.
The next architecture choice must recover ranking while creating
capacity for expert-count growth, and must then prove native LUT
cost and quality on the same stored artifact.
