# METH-160: actual E12,800 B-bank selected-path CPU component passes

**Decision: BF16 route plus selected-factor component passes both frozen CPU gates; quality and whole-model rate remain open.** The [protocol](METH_160_ACTUAL_B_BANK_CPU_COST_PROTOCOL_20260928.md) compared the actual METH-136 continued E1,280 B bank (440,401,944 bytes) with the METH-155 learned-base E12,800 B bank (4,404,019,224 bytes) on 256 varied BF16 hidden states across 24 layers. The larger bank was rejected on METH-156 external pooled BPB, so its use here measures component access cost only. The four selected B rows and 1,376,256 selected B bytes per token-equivalent are fixed across arms; total bank size grows 10×.

The [C benchmark](../../../benchmarks/native_expert_scaling/meth160_actual_b_bank_cpu.c) and [hash-binding runner](../../../benchmarks/native_expert_scaling/meth160_run_actual_b_bank_cpu.py) were committed at `47215f8` after the frozen protocol at `37cf967`. They verify all seven input SHAs, memory-map the two B banks read-only, retain the same source hierarchy/gates, and use the shared A by original parent for either source child or grandchild. The clone self-test passed exact residual equality across parent boundaries. The [machine result](meth160_actual_b_bank_cpu_result.json), SHA-256 `f789640a6b256a38da4123fa26fd63a1e922e23bfb3ffc8eb0a1d04da877ec10`, retains five paired alternating-order repetitions and 24-layer coverage for each context fixture.

| Fixture | E1,280 route+B median | E12,800 route+B median | Ratio | E12,800 unique B bytes | Gate |
|---|---:|---:|---:|---:|---|
| 256 structural-hit contexts | 3.939 ms/token | 3.964 ms/token | 1.006× | 116,766,720 | Pass |
| 256 content-miss contexts | 3.955 ms/token | 3.918 ms/token | 0.991× | 255,825,920 | Pass |

Both candidate medians are below the frozen 5.0 ms/token-equivalent and 2× E1,280 limits. Control visits 8,145 distinct source B rows across layers on either fixture; candidate visits the same number of shared structural rows on the hit fixture and 17,845 distinct content rows on the miss fixture. Route-only medians are approximately 2.49 ms/token in this measurement. The candidate's slightly lower miss median is timing noise, not an acceleration result. Peak reported process RSS is 0.983 GB; each cell completes in about 18.7 s. The C code was built with `clang -O3 -mavx2 -mfma -std=c11 -Wall -Wextra -lpsapi` and executed on the local Ryzen 5 3600X, one thread. Raw [hit](meth160_actual_b_bank_cpu_result.hit.log) and [miss](meth160_actual_b_bank_cpu_result.miss.log) logs have SHA-256 `695474996333735ab0bf07e64c978e90f77c2a89ccbcd656ff60b24e60e776b8` and `d8139ddb47fc1d40cf3a0fea80e8aaa3d230036f0efdfdc1231447293799b6a2`.

The executed runner was `.venv/Scripts/python.exe benchmarks/native_expert_scaling/meth160_run_actual_b_bank_cpu.py --out docs/research/NATIVE_EXPERT_SCALING_20260925/meth160_actual_b_bank_cpu_result.json`, automatically delayed until METH-159 exited. Its 256 METH-125 hidden states were crossed with METH-151 structural-hit or content-miss contexts, which were not captured at those same model positions. The benchmark deliberately warms the selected rows before timing; reported page-fault deltas are zero for every timed repetition. These repeated finite fixtures do not measure cold DRAM access, a compact pair-LUT bank, full `engine.c` decode, or >=50 accepted tok/s. METH-159 rejects the proposed longer training route, so this component pass cannot promote learned E12,800 capacity or quality. It does show that the actual 10× BF16 B-bank size alone did not make this selected path exceed the component budget on the tested warm workload.
