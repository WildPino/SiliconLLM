# METH-177: large RAM-resident selected LUT pool

**Uncertainty.** METH-31's Qwen-shaped ternary LUT selected path passed at E12,800 with a 5.505 GB fully allocated pool. The user's RAM-scaled target requires many more choices while keeping selected work fixed. METH-40 measured an E273,547 router sketch, and METH-160 measured the warm BF16 B bank at E12,800; neither measures `engine.c`'s selected LUT kernel against a much larger resident code pool. METH-176 failed its quality bootstrap, so this component measurement does not promote that checkpoint.

**Frozen comparison.** Extend only the METH-31 benchmark path in `benchmarks/phase60/engine.c` to admit E128,000 and 32-bit route IDs. Run the same local Clang `-O3 -mavx2 -mfma -march=znver2 -fopenmp` build and `--kselftest`, then E12,800 and E128,000 at one and six threads. Preserve L24/D896/rank8/top4, the two-trit byte-code layout, deterministic xorshift64 seed, 128 warmup tokens, four 512-token repetitions, fixed code pattern, SiLU and full output accumulation. Each pool is fully allocated and initialized before timing; no file or GPU is used. The larger pool is 55,050,240,000 bytes (51.27 GiB). The selected code bytes remain 1,720,320 per token. Run one process at a time, and compare medians of repetitions 2–4. Check identical checksums between thread counts for each E and keep every repetition, initialization time and executable/source hashes.

**Decision.** The six-thread E128,000 median must be at most 1.25× the E12,800 median and at most 5 ms/token. Report the one-thread arm as a latency diagnostic. A pass shows the selected LUT component tolerates this 10× RAM-resident pool on this host. A fail calls for a layout/kernel or access-pattern change before treating expert count as effectively free. The result never proves router selection quality, learned packed-factor quality, full `engine.c` rate, or performance at E273,547 / 100B geometry.

**Budget and stop.** Require at least 64 GiB free physical RAM before the E128,000 arm; otherwise stop and report the capacity limit. Keep pool allocation below 60 GiB, one process below 15 minutes, and no concurrent GPU or other benchmark. If allocation or initialization fails, preserve earlier completed rungs and do not extrapolate. The synthetic factors and selected IDs are not model weights or semantic experts.
