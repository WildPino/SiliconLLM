# METH-91/92: group-128 R8 tied-head refinement

## Question and frozen format

The METH-85 core plus METH-88 B-adapted E128 bank passes direct automatic external quality but fails METH-90 blind excerpt fidelity. The METH-87 over-budget BF16-head diagnostic suggested that head precision contributes to token-decision errors. Test a cheaper refinement without adding an active dense path: keep METH-85's BF16 attention, group-64 R8 FFN and FP32 controls; replace the tied embedding/output-head's per-output-row FP32 scale with one FP16 scale per contiguous 128 input weights. Use signed symmetric int8 codes in [-127,127], quantizing against the stored FP16 scale, then reconstructing to BF16. The tied matrix is stored and counted once.

The bound donor head has 136,134,656 weights, 151,936 output rows and width 896. The new head scales take 2,127,104 bytes instead of the old 607,744, adding 1,519,360 bytes. The ideal METH-91 addressed total including E128 keys and selected factors is **558,625,536 bytes/token**, below the 560,000,000-byte design limit by 1,374,464 bytes. This is arithmetic, not measured DRAM or accepted-token rate. The METH-91 exporter must verify source/checkpoint hashes, exact stored-tensor reload, and exact BF16 reconstruction from reloaded head/FFN codes and scales. Stop if physical or ideal accounting differs from the frozen ledger. One local RTX 3060, ≤15 minutes, ≤20 GiB process RSS, ≤10.5 GiB peak GPU allocation; no T4.

## Adaptation and development

The METH-88 B-only distillation recipe is applied to the new fixed METH-91 core from the original METH-56 update-512 E128 bank: 64 updates, the same pinned raw/chat training corpus, seed 88088, BF16+original E128 teacher, full-logit KL plus 0.1 teacher-margin hinge, AdamW B-only at 1e-4. A factors and product-key router remain unchanged. This keeps expert count, selected factors and routing complexity fixed while testing the head precision. Save the resulting bank as a new checkpoint with its own core hash.

Before scoring, freeze 24 source-disjoint development documents/prompts (8 code, 8 PG19 prose, 8 technical), excluding all prior IDs and overlapping 256-byte fragments through METH-90. Compare intact BF16 donor, BF16+original E128, METH-85 core+METH-88 bank, new METH-91 core with experts disabled, and new METH-91 core+new adapted E128 on identical IDs. The new arm must meet pooled document ΔBPB ≤+0.02 versus donor and each category ≤+0.04; pooled donor top-1 ≥95% and each category ≥90%; pooled top-1 no more than one point below BF16+original E128; pooled BPB at least 0.001 better than its expert-disabled core. In addition, require new-arm pooled top-1 at least 0.5 percentage point above the METH-85+METH-88 arm on this same new set to justify the added active bytes. All gates must pass before another independent generation/task/blind semantic audit. Development success alone never licenses native integration.
