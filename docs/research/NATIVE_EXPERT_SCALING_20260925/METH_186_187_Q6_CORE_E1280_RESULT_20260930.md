# METH-186/187: stored Q6 core fits bytes but loses donor rankings

**Decision.** The stored grouped-Q6 core is a reproducible compact
representation, but its direct composition with the quality-valid
centered E1280 bank fails both frozen prompt-ranking development
gates. Pooled document loss is only +0.002600 BPB against BF16+E1280;
pooled donor-top-1 agreement falls from 94.504% to 89.186%, a
**5.318-point** loss versus the allowed one point. Each category loses
more than the allowed two points. No fresh generation, task, blind
grounding or native timing test is licensed for this uncorrected core.

The [protocol](METH_186_187_Q6_CORE_E1280_PROTOCOL_20260930.md) was
frozen at `e09f01e` and amended at `403be51` to report Q6 donor as an
attribution control before model scoring. The
[exporter](../../../benchmarks/donor_adaptation/s1/meth186_export_group64_q6_core.py)
was committed at `5210192`; the
[four-arm scorer](../../../benchmarks/native_expert_scaling/meth187_q6_core_e1280_development.py)
at `1c92fc7` before its run. Both bind Qwen2.5-0.5B-Instruct revision
`7ae557604adf67be50417f59c2c2f167def9a775`, BF16 source SHA-256
`fdf756fa7fcbe7404d5c60e26bff1a0c8b8aa1f72ced49e7dd0210fe288fb7fe`,
and METH-85 stored-core SHA-256
`c484a1130e495342d1b8644ff156cc002d0fd68fe12230604e59f35d3af6433a`.

METH-186 keeps the exact METH-85 R8 tied-head codes/scales, BF16
attention and FP32 controls. It packs four signed symmetric Q6 FFN
codes per three bytes, with one FP16 scale per 64 input weights.
All 363 stored tensors reload byte-exactly, and all 72 FFN BF16
reconstructions match the values before serialization. Maximum
per-matrix FFN relative weight L2 error is 2.838%. The local physical
artifact at `results/native_expert_scaling/meth186_qwen05b_instruct_group64_q6_core.safetensors`
is 470,294,752 bytes, SHA-256
`f68ed7ba06eb38a19d883310c86d9e569bf719e726a664a6287edb463d3ae725`.
Its core tensor payload is 470,254,592 bytes. The exact
[export ledger](meth186_group64_q6_core_export.json), SHA-256
`70b325aca75eff11f03fe0afbd9aab5cb218d9e41ebf5b79e1627dc05c58f6b2`,
prices 5,652,480 parent-router bytes, 2,752,512 child-projection
bytes, 122,880 selected-child-key bytes and 2,752,512 selected
shared-A/B factor bytes. The **ideal addressed total is 481,534,976
bytes/token**, leaving 78,465,024 below the 560 MB design allotment.
These are format/selection calculations, not measured DRAM traffic or
C rate. The separate full E1280 bank remains resident in RAM.

METH-187 reproduced every original METH-122 BF16 donor and centered
E1280 document negative log likelihood exactly, along with all 24
E1280 donor-top-1 match counts. It then changed only the stored core's
head and FFN. The 24 documents and prompts were already consumed by
METH-121; these are development diagnostics, not new quality evidence.

| Same 24-source measure | BF16 donor | BF16+E1280 | Q6 donor | Q6+E1280 |
|---|---:|---:|---:|---:|
| Pooled BPB, 98,280 bytes | 1.189813 | 1.184887 | 1.192527 | 1.187487 |
| Donor prompt top-1, 4,494 positions | 100% | 94.504% | 89.008% | 89.186% |

Q6+E1280 minus BF16+E1280 BPB is +0.002215 code, +0.002558 prose,
and +0.003026 technical, passing every frozen document limit. Its
donor-top-1 changes are −6.811, −4.365 and −4.571 points by those
categories, failing every category ranking limit. Q6 donor and
Q6+E1280 ranking are close; the existing expert bank does not undo
the compact-core ranking loss. This comparison does not isolate the
R8 head from the Q6 FFN, nor prove that a low-rank correction will
repair either organ.

The [raw four-arm result](meth187_q6_core_e1280_development_result.json),
SHA-256 `7ec10c7fe1de942bfb40be77f813b83888d6d658d0a8ec844beef96822f46e1c`,
holds every document/prompt row and category. Export took 9.703 s,
4.242 GB end RSS and 121.8 MB peak GPU allocation; scoring took
45.188 s, 2.934 GB end RSS and 4.269 GB peak GPU allocation on the
local RTX 3060. No T4 was used.

```powershell
.\.venv\Scripts\python.exe benchmarks/native_expert_scaling/meth187_q6_core_e1280_development.py --out docs/research/NATIVE_EXPERT_SCALING_20260925/meth187_q6_core_e1280_development_result.json
```

Both commands refuse to overwrite their outputs; a replication run
needs new paths and the scorer's core binding adjusted to that new
export. The concrete next question is whether jointly trained,
stored low-rank corrections to the tied head/embedding and FFN can
restore the donor's rankings and grounded responses while staying
inside the 78.465 MB/token margin. Such a correction needs its own
frozen training/data and source-disjoint quality protocol, followed
by native C cost and same-artifact rate. The current result does not
show any of those gates, nor transfer to GigaChat 10B/100B.
