## Source information, duplicates and geometry

Require ALL48 original conversation IDs represented, exact32 FIT/16 reserved
DEVELOPMENT, byte-qualified BF16 normalized x and complete original y. One
original timed-out conversation contributes only its saved complete forward
prefix; it is not a completed generation. All completed source responses are
reused. No new original forward, tokenizer or full-model control runs.

Keep conversation separation. Exact common-prompt x duplicates across partitions
must be reported. They are not independent geometric directions. FIT row weight
is1/(FIT multiplicity of that exact BF16 x). Each unique x therefore has total
unit fit mass, without discarding possible source BF16 response-rounding
differences. Retain all original y and occurrence provenance. DEVELOPMENT
primary error uses ONLY x bytes absent from FIT, with reciprocal multiplicity
among those novel DEVELOPMENT x. Report full occurrences and prompt/generated
rows separately. This is reserved component development, never fresh final chat.

Construct covariance/eigendecomposition in CPU F64 from unique FIT x only.
Top32 eigenvectors, descending eigenvalues; first maximum-absolute coordinate
positive. Divide the projection by sqrt(sum of those32 eigenvalues), yielding
unit average centered query squared radius. No whitening, mean bias in the
runtime projection, development input or y enters geometry. Query=q=P*x;
center distances cancel a common translated mean algebraically. The radius
normalization is fixed before observations and avoids arbitrary score units.

Unique FIT rows use NumPy's lexicographic BF16-bit row order, with retained first
occurrence indices. Farthest-first initialization: first FIT query nearest its mean, then maximize
nearest-center squared distance; first/lower input index breaks ties. Exactly
20 Lloyd updates, squared Euclidean/F64 means, preserve an empty center (report
empties). Build16 parents from all unique FIT queries. Freeze parent centers
asF32. Stable top4 parent score2*q*c-c^2 and selected-score softmax exactly match
the actual block. Build10 children per parent from the unique FIT rows that
actually select that parent; same farthest-first/20 updates. Children do not
change parent choice/mass. Use F32 route arithmetic/ascending IDs throughout
the physical block. E16 has one function/parent and no child score computation.

Before fitting require each of ALL160 leaves >=8 distinct FIT x from >=2 FIT
conversations AND >=4 distinct novel DEVELOPMENT x. All16 parent functions
must meet the same bounds. Report actual mass energy as well as selected count;
selection alone does not imply influence. A failure stops fitting: diagnose
support/geometry without filling missing labels, fallback or extra clusters.
This is a conservative finite eligibility policy, not a proof that any such
threshold guarantees learnability or that unseen regions are impossible.

## Fixed eligibility gates and interventions

Require E160 final F32 AND BF16-rounded-coefficient novel DEVELOPMENT RMS<=1%
of complete source response energy; each of16 categories <=3% RMS in both
encodings. Report squared ratio AND its square root unambiguously. The strict
local policy is motivated by prior477-R1's2.83% FFN RMS changing a head winner;
1% is not a guaranteed whole-model semantic bound. Also require E160 squared
error<=0.90*E16 on the SAME novel rows for both encodings.

ALL160 serialized BF16 leaves must have distinct hashes, and each must change
from its own original initializer. To test routing usefulness, cycle child
ID+1 modulo10 WITHIN EACH unchanged selected parent, preserving parent IDs,
mass, shared output and four active calls. Require novel DEVELOPMENT squared
error at least1.10 times actual E160 error. Report per-category and per-leaf
selection/mass/error intervention. Distinct hashes/updates alone never imply
useful additional source capacity. This finite10x comparison is not a large-n
CPU LUT/normalizer/DRAM qualification.

ALL fixed gates must pass to permit a24-layer conversion. Otherwise close this
finite initializer/geometry/update recipe and diagnose support, fit versus
generalization, encoding or ineffective functions. Do not increase widths,
updates, thresholds, regularization or projector rank after values. A failure
does not refute all jointly learned representations or arbitrary redundancy.
