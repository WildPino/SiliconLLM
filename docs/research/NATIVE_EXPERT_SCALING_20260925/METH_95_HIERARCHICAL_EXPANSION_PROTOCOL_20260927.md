# METH-95: function-preserving E128→E1280 hierarchical expansion

The METH-71 E1280 recipe trained 1,280 learned slots from a zero-output start but failed external utility and blind semantics. Test a different **starting geometry**: expand the quality-audited METH-56 BF16-donor E128 product-key bank tenfold while exactly preserving its step-zero function. Each of 128 parent experts owns ten child slots. Copy both parent rank-8 A and B factors into every child initially. Keep the learned parent rank-64 product-key top-four route and its four-way softmax unchanged. For each selected parent, project the hidden vector once to 32 dimensions, score its ten child keys, and select exactly one child. Child keys are fixed seeded sketches for this preflight. Because all ten child factors initially match their parent, child choice must not affect the residual output. Four child experts remain active per token/layer. This is a function-preserving *initialization*, not evidence of learned child capacity.

Bind exact donor and METH-56 checkpoint hashes. On fixed raw and chat token sequences, require bitwise-identical parent/expanded final logits and greedy tokens, equal selected parent route/gates, 1,280 addressable child slots, and a source-bound count of how many child slots are actually visited. Fail before training if exact output parity or active top-four is lost. Count resident A/B factors, parent keys, child projection/keys, and selected factor bytes. CPU timing and cold DRAM behavior are separate; do not infer them from GPU parity. One local RTX 3060, ≤10.5 GiB allocated GPU memory, ≤20 GiB process RSS, ≤15 minutes. No T4.

Only after this exact preflight may a separately frozen training rule make children distinct and test whether quality remains donor-relative as expert count rises. Copying factors alone does not satisfy the user's large-N quality requirement. The compact-core semantic failure and missing full `engine.c` rate remain independent unresolved gates.
