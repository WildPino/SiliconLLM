## Large n: storage, search and useful capacity

For fixed D and r, private storage grows as n*D*(D+r), while one selected
function's work and weight reads are independent of n. Product keys with
n=I*J evaluate I+J affine scores. Balanced axes give O(sqrt(n)*(D+r))
choice/control work for this candidate's separable score, not flat O(nD).
This is an algebraic property of the candidate, not donor routing fidelity.

The current dictionary uses four rows per ID at n=128. Extending that rule
to every new ID would make r=4n and increase active work. The eventual scaling
procedure must hold an explicit active dictionary budget, or develop and
measure selective dictionary access. 494 does not specify such a conversion
for n=1280 and does not grant it eligibility.

Adding experts also changes donor normalization:

```
p_old,new = p_old,old / (1 + Z_extra/Z_old).
```

Consequently a weighted function calibrated at n=128 does not automatically
transfer unchanged to n=1280. Useful capacity requires original/new distinct
functions, exposure and causal utility, fresh quality and physical DRAM
measurements. More stored slots and an algebraic sublinear search do not
complete that demonstration. Actual ~100B values are still unavailable;
397 headers do not constitute a transferred model.
