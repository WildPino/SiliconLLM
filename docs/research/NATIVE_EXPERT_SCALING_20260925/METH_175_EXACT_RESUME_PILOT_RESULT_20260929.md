# METH-175: exact-resume pilot result

The 16-update candidate pilot was run in two processes on the frozen first 16 METH-175 draws. The first process intentionally stopped after writing and publishing an exact checkpoint at update 8. Its snapshot pointer recorded 16,285,855,139 bytes and metadata SHA-256 `a26595db612acd29321b5b4822877cfbdcbc5ce87f8304a9d25c721df1f9fbf1`. The second process loaded that snapshot, completed updates 9–16, wrote a compressed lossless snapshot of 10,696,507,568 bytes, exported and read back the combined BF16 bank, and removed temporary checkpoint scratch. The result JSON SHA-256 is `f028f1a98bb30c18d7bf35d6e85f17dadb88677ac3962651758589f2cd6bac0f`.

The resumed run's 16 per-update records compare exactly equal to the earlier uninterrupted METH-175 pilot. Its final bank SHA-256 is `000540b77640ee00736640cd0ffe45f242da57611b94d63d82d26ace58ab9077`, also exactly equal to that pilot's 4,404,019,224-byte bank. The initial BF16 parity, source/routing, optimizer and combined-bank readback gates all pass. Every layer records 16 combined-bank audit checks. The accumulated active runtime is 986.234 seconds, under the pilot's 20-minute cap. This test establishes exact recovery for this pilot interruption; it is not a full 3,840-update training or held-out quality result.

The first resume attempt was deliberately stopped before additional updates after identifying that snapshot serialization copied large CPU tensors. The completed resume uses direct synchronous serialization with lossless Zstandard compression. During its final snapshot, observed working set was about 35.5 GiB, below the 52 GiB cap. The initial uncompressed update-8 snapshot remains compatible with the compressed reader, establishing backward compatibility for the interrupted pilot. The intentional failure and the process traces remain local evidence.
