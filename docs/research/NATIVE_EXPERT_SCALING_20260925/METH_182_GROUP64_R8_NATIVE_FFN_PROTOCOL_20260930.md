# METH-182: actual stored grouped-R8 donor FFN native feasibility

**Uncertainty and prior evidence.** METH-129's real Qwen0.5B-Instruct native FP32-core+E1280 decode reaches 20.791 tok/s with an exact two-pass head; its six-thread FFN profile is 38.637 ms/token. METH-85 has a 557.106 MB/token ideal active-byte grouped-R8 core+E128 design, but METH-90 rejects that core's blind semantic quality and no native grouped-R8 FFN timing exists. Before another costly core adaptation, determine whether the actual stored grouped-R8 FFN can lower this dominant CPU component enough to leave a plausible full 20 ms/token budget. This is a component feasibility test, not promotion of the quality-rejected core.

**Frozen artifacts.** Read only the METH-85 grouped-R8 safetensors core SHA-256 `c484a1130e495342d1b8644ff156cc002d0fd68fe12230604e59f35d3af6433a`, taking exactly 24 layers × gate/up/down `.q` int8 rows and `.scale` FP16 group-64 scales. Export them unchanged into a compact C-readable binary and re-read every byte. Use the existing [METH-125 E1280 actual pre-MLP hidden-state capture](meth125_e1280_capture_result.json), SHA-256 `f7af00b4b4ce417664848950770f63b78520ca3c983748a692640704c203b699`: 256 varied tokens × 24 layers × 896 BF16 values. These states come from the BF16 E1280 assembly, **not** from the METH-85 core; they are a real-input component fixture, not a full-model trace.

**Operation and checks.** The C kernel reads each input BF16 vector, quantizes 64-element groups symmetrically to int8, evaluates the original METH-85 int8 codes with the stored FP16 group scales using an AVX2 signed dot, applies SiLU(gate)×up, and computes down in the same way. Use six local Ryzen 5 3600X CPU threads; compare 16 predetermined positions (first 16 of 256) at all 24 layers to a PyTorch reconstruction of the same stored core on identical BF16 inputs. Report median and maximum layer-output relative L2 error. Require ≤1% median and ≤5% maximum for numerical feasibility. Time three full passes over the 256×24 input states, excluding file loading and reference computation; report median 24-layer FFN ms/token. The six-thread CPU feasibility gate is **≤10 ms/token**, leaving roughly 10 ms for head, attention, routing, selected experts, cache and control under the 20 ms goal. A pass only warrants full integration and quality work; it cannot prove 50 accepted tok/s.

**Budget and stop.** Local CPU for C timing, local RTX 3060 permitted only for the PyTorch numerical oracle, never T4. Stop at 15 minutes wall, 8 GiB C RSS or 10.5 GiB GPU allocation; reject wrong input SHA, tensor shape/type, export readback, nonfinite output, unsupported CPU ISA, or failed numerical gate before promoting cost. Preserve failure and partial results. Do not rerun the paused GigaChat donor-port producers. No new corpus or model training is part of this cell.
