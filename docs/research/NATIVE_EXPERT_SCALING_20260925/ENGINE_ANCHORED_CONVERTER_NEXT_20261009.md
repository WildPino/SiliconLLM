## Decision and what changes

The endpoint remains a useful pretrained CHATBOT transformed into the original
LUT/ternary/compact SSM/SWA engine. A source-compatible or wider intermediate is
permitted offline; its active donor cost cannot become the endpoint by default.
The original701.7/s is measured small/cache-model evidence. It establishes a
fast computational mechanism; complete large-n routing/DRAM and useful chatbot
conversion remain separate questions. The present target uses8.891x counted
matrix work and7.089x useful state payload versus the original default.
Unchanged LUT function bodies do not recover that original cost envelope.

The previous comparison improves FIT without meeting DEV transfer criteria;
2+6 has no selected advantage. Preserve all actual A344/B344 states and failures.
Stop using further small allocation changes or same-corpus dose as the default
next step. The current n72 bank's quarter-source coefficient count also compressed
stored capacity. A converter must allow more stored distinct functions without
automatically making the recurrent controller or selected expert width larger.

**Selected first work:** implement the capacity/storage contract under an
explicit original-engine reference geometry, before another recovery pilot.
This removes a concrete endpoint incompatibility. It is an enabling stage,
not evidence that a larger untrained bank preserves knowledge. The present
D512/L12 learner remains a retained research intermediate; it has no endpoint
quality/rate admission. Width/depth changes in any future endpoint require their
own measured cost/quality reason.

## 3. Two different information problems in the conversion

For donor atom responses a_j(x), overlapping expert functions
g_e(x)=sum_j c_ej a_j(x) and selected coefficients alpha_e(x) reproduce a dense
sum only when the needed response is covered. If atoms are linearly independent,
sum_(e in S) alpha_e c_ej=1 for each needed atom; dependencies can relax this.
Normalized top-k of copied disjoint groups does not preserve a dense sum.
Extra stored leaves can support overlapping coverage; duplication alone does
not make the coefficient or coverage identity hold. Adaptation must learn useful
query-dependent functions and coefficients, then test interventions/removal.

Separately, the compact state is an encoder of history. If two histories give
exactly the same complete state/query but require different donor distributions,
any deterministic bank/router using only that state produces the same response.
More static experts cannot distinguish that collision. This is an algebraic
condition, not evidence that our current encoder necessarily has such collisions.
Local source FFN error, projected matrix energy and cached-prefix KL do not
measure a universal information floor. Core/state transfer and conditional
response coverage need separate diagnostics, followed by whole own-history tests.

The working pipeline therefore needs: a compatible source/operator map;
source-informed bank extraction with coverage/redundancy; compact transition and
readout adaptation; training through the deployed ternary/AQ/LUT arithmetic;
learned cheap addressing; joint chatbot recovery; versioned export and fresh
same-artifact quality/rate. None of the missing stages is declared validated.

Reuse the actual five-family [screening](CHATBOT_ENGINE_TARGET_TRIAGE_RESULT_20261008.md)
and [research synthesis](CHATBOT_ENGINE_TARGET_REASSESSMENT_20261008.md).
Falcon1.5B is the current useful instruction donor; FalconTiny's failed usefulness

Qwen offers a Transformer variant. Granite/BitNet metadata advantages alone do
not certify weights/quality/applicability. Select families by transition,
activation, expert-function and interface compatibility plus measured conversion
cost, rather than choosing a generic source runtime as the final architecture.

A month-plus T4 conversion is allowed after a concrete staged recipe. Measure
teacher supervision coverage, novel generated student histories, recovery versus
compute, actual FP16-compatible throughput and storage/optimizer transfers before
communicating reason/GPU-hour budget/checkpoints/plateau stops and allocating it.
Current24 FIT cases/4422 labels cannot price broad knowledge transfer.

Dense F32 parameters+gradients+Adam require16P bytes (160GB/10B,1.6TB/100B).
GPU block residency alone does not solve host/disk capacity. Dormant F32 masters
and both moments still require12P before active gradients if retained. The union
of experts touched across a training sequence can be much larger than k; price
that union/backward lifetime, not merely per-token inference selection. Candidate
bounded block/adapter or frozen-bank methods need explicit learning semantics,
resource and quality evidence; sparse inference does not imply sparse optimizer
allocation. Time on a T4 is a conversion resource, not a substitute for those
memory and information constraints.
