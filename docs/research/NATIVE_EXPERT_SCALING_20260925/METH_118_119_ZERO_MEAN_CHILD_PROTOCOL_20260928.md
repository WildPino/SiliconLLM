# METH-118–119: preserve the E128 parent mean while selecting distinct children

METH-117 rejects the alpha=0.75 E1280 candidate on arm-blind external semantics despite passing all automatic gates and showing a small selected-child BPB advantage. A weight-only diagnostic on the frozen METH-107/METH-56 checkpoints finds the per-parent common B displacement has 0.332–0.348 times the RMS of the child-specific displacement across 24 layers. The common displacement is smaller in norm, yet the METH-116 parent-mean ablation accounts for most of the candidate's pooled BPB gain. Test whether removing that common mode protects grounded response fidelity while retaining useful child-specific choices. This is a new transformation, not a reinterpretation of the viewed METH-115 responses.

For every parent expert and layer, compute the arithmetic mean of its ten METH-107 child B factors in FP32. Define `B_centered_child = B_METH56_parent + (B_METH107_child - mean_10(B_METH107_child))`. Keep all METH-56 parent routes, METH-107 child routes, A factors, BF16 dense donor and four active parent slots fixed. No training or alpha selection occurs. The ten transformed child B factors have exactly the parent B as their FP32 mean up to reduction rounding. Replacing every selected child factor by that parent mean is a no-child control expected to reproduce E128; verify it on actual input IDs before interpreting a quality comparison. Require at least 640 child slots per layer with a maximum B-coordinate difference >0.001 from sibling zero after the transformation. This distinguishes factors but does not by itself prove useful choice.

METH-118 freezes 24 new development documents and prompts before inference: eight code, eight prose and eight general technical. Draw prose from separate books in pinned PG19 train shard 00002. Exclude source IDs and overlapping text fragments from all prior calibration, development and external manifests through METH-115. The Git code/technical pool can supply new file IDs and fragments but remains a shared domain. Bind source-book, text and token hashes.

METH-119 compares intact BF16 donor, BF16+METH-56 E128 and centered E1280 on identical IDs. Require centered E1280 pooled BPB at least 0.00005 below E128, as a direct child-choice utility floor because the no-child control equals E128. Also require each category E1280−E128 BPB ≤+0.02, pooled donor prompt top-1 difference ≥−0.01 and each category ≥−0.02. For 128-token greedy continuation, require centered E1280 EOS count ≥E128−2, and no more than one extra repeated 8-gram or early non-EOS answer pooled or per category. If automatic gates pass, perform an arm-blind excerpt-only semantic development review: commit unsupported, severe and missing-supported-detail judgments before revealing arms; centered E1280 must not exceed E128 in any count. A passing development screen permits a separately frozen external audit on new sources, including full PIQA and the same blind semantics; it is not quality promotion.

Use the local RTX 3060 only. Stop each development evaluation at 15 minutes, 10.5 GiB allocated GPU memory or 20 GiB RSS. No T4. The transformation is FP32 weight arithmetic followed by the existing BF16 model path; it does not establish native C/LUT factor arithmetic, full `engine.c` execution, or 10B/100B scaling. If centered child choice fails the BPB utility floor or semantic gate, stop this rule instead of weakening those thresholds on the same set.
