# METH-182: actual grouped-R8 FFN misses native cost and numerical gates

**Decision: stop this grouped-R8 native FFN path at the component gate.** On 256 real BF16 E1280 pre-MLP states per layer, the C AVX2 kernel takes **12.829 ms/token** median across three passes through all 24 FFNs, above the [frozen 10 ms limit](METH_182_GROUP64_R8_NATIVE_FFN_PROTOCOL_20260930.md). Against the same stored core reconstructed in PyTorch on 16 predetermined states/layer, its output relative L2 error has **1.896% median** against a 1% limit; the maximum is 4.515%, within its 5% limit. Both cost and joint numerical gates fail. This is a component rejection, not an end-to-end rate or model-quality measurement.

## Artifacts and execution

- The input is the existing METH-85 Qwen2.5-0.5B-Instruct grouped-R8 core, SHA-256 `c484a1130e495342d1b8644ff156cc002d0fd68fe12230604e59f35d3af6433a`. The [exporter](../../../benchmarks/native_expert_scaling/meth182_export_group64_ffn.py) copies exactly 24×gate/up/down int8 tensors and their FP16 group-64 scales, verifies their shapes and performs a byte-for-byte readback. The resulting 323,592,216-byte local binary at `results/native_expert_scaling/meth182_group64_ffn.bin` has SHA-256 `d8f578ab42b99258339c2cfe0ee846e01537e5f4f49cae68c9bcdba7112b5613`; its [export report](meth182_group64_ffn_export.json) binds all 72 tensor byte hashes. Export took 13.110 seconds, ending at 730,935,296 bytes RSS.
- The varied inputs are the existing [METH-125 E1280 capture](meth125_e1280_capture_result.json), SHA-256 `f7af00b4b4ce417664848950770f63b78520ca3c983748a692640704c203b699`, shaped 256 tokens × 24 layers × 896 BF16. They came from the BF16 E1280 assembly, so they do **not** trace the quantized METH-85 core's hidden states. No new corpus or model training was used.
- The [C benchmark](../../../benchmarks/native_expert_scaling/meth182_group64_ffn_cpu.c), executable SHA-256 `0f75043362a2058bdd5259227ec14ca444ece8d92225cad3510a93704347c9c7`, reads actual stored codes/scales, quantizes each input group symmetrically to int8, uses AVX2 signed 64-element dots, then computes SiLU(gate)×up and down. Six local Ryzen 5 3600X CPU threads run three full 256-token passes after the 16-token correctness output. The [raw timing](meth182_native_timing.json) is **13.211, 12.829, 11.682 ms/token**, median 12.829. The final pass alone also misses 10 ms. Peak C working set is 339,771,392 bytes, below 8 GiB.
- The [independent checker](../../../benchmarks/native_expert_scaling/meth182_check_group64_ffn.py) reconstructs the same stored tensors as BF16 and executes PyTorch gate/up/SiLU/down on the same first 16 states at every layer. All 384 C outputs are finite and uniquely matched by token/layer; 380/384 exceed 1% relative L2, none exceeds 5%. The maximum 4.515% occurs at token 0, layer 17. The [machine result](meth182_group64_ffn_result.json), SHA-256 `f03ad1500c07b0298baeb2361815a8b037d8d6bd1b71349127a4e3a1bf013225`, records all rows and bindings. PyTorch oracle peak GPU allocation was 61,089,792 bytes on the local RTX 3060; no T4 was used.

## What the failure means

The 12.829 ms FFN component leaves only 7.171 ms within a 20 ms full-token target. The METH-129 FP32 reference already charges 4.179 ms to its two-pass head plus 2.801 ms QKV and 2.136 ms output projection, before routing, selected experts, KV/control and other work. These are **separate run measurements** and cannot be summed as a measured end-to-end bound for a new artifact, but they show too little margin to promote this exact kernel/core combination. The numeric comparison includes both the C input int8 quantization and BF16 rounding differences from the PyTorch reconstruction; it does not isolate their contributions. METH-90 had already failed blind semantic conservation on the grouped core. Improving only this kernel without a quality-valid core and distinct useful experts would not close the goal.
