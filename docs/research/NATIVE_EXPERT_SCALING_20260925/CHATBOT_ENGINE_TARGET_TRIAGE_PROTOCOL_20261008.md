# Target-aware donor triage: prospective protocol

8 October2026. Implements the next step in the engine-target reassessment.
Question: which actual donor architecture provides a feasible first adaptation
route into compact recurrent core + useful selected ternary LUT functions?
Metadata and dimension accounting only; no source inference, training or speed.

## Inputs and code freeze

Freeze `chatbot_engine_target_acquire.py`, `chatbot_engine_target_triage.py`
and this protocol before acquisition/accounting. Acquisition binds existing
Qwen/Giga qualified census bytes, actual local configs, local Granite hybrid
config and matching local Transformer operator code, original engine code and
target contract. New public FalconTiny/BitNet configs are fetched at pinned
40-hex revisions; API/config bytes are retained. No weights or remote code are
downloaded/executed. Metadata source strings remain data.

Acquisition uses a unique new directory, max5MiB per input/HTTP body,20s network
timeout, checks100s elapsed before HTTP operations. This is not a hard120s job
watchdog or a full acquisition RSS qualification. Preserve partial directories
on failure. No completed source/header/function/model observation is replayed.

Offline accounting validates all bound config/census/support/acquirer hashes.
Run Python3.12.10 with -I -S -B -Xutf8; stdlib only, no tensor libraries or
subprocesses. Existing corpus/checkpoints/endpoints are untouched.

## New analysis and invariant distinctions

Reuse Qwen/Giga original matrix/category counts from retained qualified census.
For new Falcon/BitNet/Granite, derive matrix products from actual config and
manually inspected bound operator shapes, including all attention/SSM branches,
expert gates, shared experts and full readout. Config-derived counts are not
complete tensor-header counts or weight cardinality verification.

For each vocabulary, price two PROSPECTIVE original-engine core shapes:
D256/L6/oneSWA and D512/L12/twoSWA, Mamba1 expand2/state96/dt_rankD16,
window128,top8/h128. n per layer is32,128 and the ceiling required for10B/100B
gated expert coefficients. These large pools are untrained accounting cases.
Do not infer their quality or capacity from their byte count.

Count core projections, F32 sensitive/scalar organs, separate embedding/head,
norms, ternary codes and row scales, default full linear router, fixed recurrent/
SWA state, and F32 master+gradient+two moment storage (16B/trainable coefficient).
Count both byte-pair and nibble-pair layouts with actual coefficient alignment.
Legacy MoE loader has4B F32+1B unpacked ternary+packed codes per expert coefficient;
packed-only proposal omits mandatory reference copies. Exact row scales remain.

Include a PROPOSED fanout32/query32/beam8 routing tree, padded persistent keys,
query projection and conservative per-step matrix-work bound. It is not an
implemented CPU LUT route, nor exact search of arbitrary donor/flat scores.
Structured mass and useful routing must be trained and actually checked later.

## Resources, decisions and stopping

Offline analysis <=60s/256MiB observed process peak/<=5MiB output; read-only
bound inputs, one exclusive result file, no scientific concurrency. These are
ordinary metadata apparatus checks, not new quality/throughput gates. Record
pre-serialization and final command elapsed/peak scopes honestly; do not claim
through-exit audit from a sample. Retain any first fault rather than overwrite.

Stop at missing fields/unsupported shapes/hash/resource faults. No implicit
default activation/precision or weight alias, and no favorable omission of
source branches. Integer shape/count consistency and source-category sums
must hold; independent hand calculation of decisive target terms accompanies
the result. Broader testing is unnecessary for this metadata stage.

Decision after observed report: select one actual first donor/core/ternary
adaptation route and identify the first learned or source-information prerequisite.
Structural affinity alone cannot justify source-shaped porting or a large weight
download. Sparse inference cannot be mistaken for dense-Adam memory feasibility.
No T4 starts here; actual reason/budget/stops will precede its use. Fresh chatbot
quality+accepted50 SAME artifact/useful n/physical DRAM/further families remain.
