# METH-164: prospective cross-source and context-length route validation

**Uncertainty and decision.** METH-162's 138-entry structural table repairs the METH-159 hot-parent failure on the same inputs that exposed it, while median content support remains 39 <50. Test whether the table's load improvement survives a different text source and context segmentation before considering larger matched training. A pass makes this route eligible for a separate expanded-data support screen and native CPU cost check; it does not license training or establish quality. A failure rejects this fixed table as the tenfold candidate. METH-163's prefix-only route is rejected and is not retuned here.

**Frozen data.** Use local PG19 train shard 10, `data/external/pg19/data/train-00010-of-00023-dd5d8583a9f6a549.parquet`, SHA-256 `ed08834a0a5d4b63af11f94595561fb6988693ff3a75eacbf6e1a934cec39f78`, separate from the METH-158 H0 training stream and reserved shard 9 quality set. Deterministically rank shard-10 row IDs by SHA-256 of `meth164-cross-source-route-164164|part|row`, taking 128 chat rows, 128 distinct raw rows and 24 further document rows. Decode a source span starting at token offset `256 + SHA-256(seed|offset|row)[:8] mod 512`, using the pinned Qwen2.5-0.5B-Instruct tokenizer; require enough tokens for 1,024-token document windows. Use 96 span tokens in the exact METH-43 summary prompt template, 128 raw tokens and 1,024 document tokens respectively. Bind every selected row, span ID hash, prompt/window hash, source-text hash, shard hash, tokenizer fingerprint and METH-162 table hash in a manifest **before** donor generation. Require disjoint row IDs among partitions. No PG19 shard-9 content may be read.

Generate one greedy BF16 donor continuation, up to 128 tokens, for each of the 128 frozen prompts with cache enabled. Shard output for resumability, hash prompt/continuation IDs and report EOS/repetition. Then use the frozen centered E1,280 source model to record four source-child IDs per token/layer for: 128 prompt-plus-continuation sequences (excluding the final target), 128 raw 127-token inputs, and the 24 documents segmented independently into widths 128 and 512, resetting previous ID/local position at each segment as in METH-150. Require eight-prompt BF16 teacher/control parity. Replay both the original 75-tuple rule and the frozen 138-tuple METH-162 table on the identical source-child choices; keep all 24 layers' slot counts, token totals, structural traffic, coverage, maximum-load ratio, and hot-parent grandchild share. Do not change either table, hash, source selection or thresholds after observing the data.

**Prospective route gates.** For the proposed table, every one of the four cells and 24 layers must have at least 4,000 occupied content slots, global content maximum-load ratio <=1.25, and worst hot-parent grandchild share <=25%, with hot parents defined exactly as METH-150 (at least 250 content selections). Require at least one hot parent in every cell/layer, exact source-child/grandchild identity, four selections per input token/layer, and nonzero shared traffic in the chat cell. The old route is a paired comparison, not a fallback if the candidate fails. Report its same metrics even when the candidate passes.

**Cost and stop.** Only local RTX 3060 and CPU; no T4. Teacher generation cap 20 minutes, model route-forward cap 20 minutes, each with <=10.5 GiB allocated GPU memory and <=20 GiB RSS; manifest cap 5 minutes/8 GiB RSS. Stop on the first hash, parity or resource failure. A route pass still leaves median training support, native CPU table cost, long matched E1,280/E12,800 training, untouched quality and same-artifact >=50 accepted tok/s open. PG19 shard 9 remains unused for the eventual external quality audit.
