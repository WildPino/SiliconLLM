# Roadmap status — 21 September 2026

This update records the completed STRAT-01 GigaChat 3.1 paired document
rollout. Earlier source-binding, fresh-BPB, and PIQA results remain as recorded
in [STATUS_20260920](STATUS_20260920.md); this result supersedes only that
status's statement that the full rollout arms were next.

## STRAT-01 document rollout

The frozen paired 96-document rollout is `PASS_DOCUMENT_ROLLOUT`. Q4 produced
two newly degenerate documents, both `loop8x3` in code; BF16 had no code or
prose degeneration and one `technical_general` degeneration. The registered
failure threshold is at least three Q4-only degeneracies, so the gate passes
by one. Both arms generated 256 tokens per document on average and had zero
EOS terminations, `run32`, or `empty` events. Exact generated sequences match
on 1/96 documents; the mean common prefix is 15.104166666666666 tokens, a
diagnostic only.

See the [canonical result](../donor_adaptation/probes/STRAT_01_GIGACHAT31_DOCUMENT_ROLLOUT_RESULT_20260921.md)
and raw adjudication at
`benchmarks/donor_adaptation/density/results/strat01_gigachat_rollout_v1/rollout_adjudication.json`.
The measured runtime totals are reference-runtime quality-run durations, not
accepted-token throughput; they do not belong in `SPEED_LEDGER.md`.

## Remaining gates and next step

This pass applies only to the frozen document-rollout gate. HumanEval remains
`PENDING_SANDBOX`. Tokenizer/operator parity in `benchmarks/phase60/engine.c`,

## STRAT-01 C-engine parity rung 0

The accepted Q4 artifact now passes [engine rung 0](../donor_adaptation/probes/STRAT_01_GIGACHAT31_ENGINE_RUNG0_RESULT_20260921.md).
At committed engine revision `10a44b5`, the early-dispatched native C path
verifies the exact 6,474,702,976-byte file and SHA-256, parses GGUF v3 in
bounded memory, and emits all 414 tensor descriptors. The descriptor digest
is exactly equal to the pinned llama.cpp reader, and all 414 names/shapes
match the BF16 source-binding report. The final apparatus also passes its
malformed/substitution controls and the historical engine kernel self-test.

This is an identity/layout pass only. The 25.96-second full-file hash is not a
load-time or rate measurement and is excluded from `SPEED_LEDGER.md`.
Dequantization, matrix orientation, quantized kernels, DeepSeek2 operators,
tokenizer semantics, logits, greedy decoding, C-path quality, RAM, and the
>=50 tok/s lower-CI target remain open.

The [engine compatibility audit](../donor_adaptation/audits/STRAT_01_GIGACHAT31_ENGINE_COMPATIBILITY_AUDIT_20260921.md)
now identifies the tokenizer, operator, layout, and container mismatches. It
also establishes that the Qwen-oriented `donor_engine.c` is only a source of
implementation patterns, not a semantically compatible execution path.

Rung 0 is closed and must not be repeated. Proceed with a separately frozen
rung 1: one named tensor, fixed deterministic inputs, scalar reference over
the exact GGUF blocks, and numerical comparison through a reusable C matvec.
Q4_K, Q5_0, and Q6_K each require direct parity evidence before the program
generalizes to layer or full-model execution. Do not begin a quality or rate
claim from the identity/layout pass.
