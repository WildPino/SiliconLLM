## STRAT-01 GigaChat base-model gate progression

The pinned GigaChat 3.1 base-model pair now has three consecutive quality
results on identifiable artifacts:

1. `PASS_SOURCE_BINDING`: all 414 base tensors and 21,350,179,072 payload
   bytes in the clean conversion match the producer BF16 GGUF.
2. `PASS_FRESH_BPB`: on 96 new documents, Q4 minus BF16 is
   +0.0123234362 BPB with upper one-sided CI95 +0.0135548442, below +0.02.
3. `PASS_PIQA`: on the preregistered 1,838-item set, BF16 is 1,466 correct
   and Q4 is 1,456. The registered requirement is 1,437, so Q4 passes by 19.
   The descriptive paired accuracy delta is -0.0054407 with two-sided CI95
   [-0.0168662, +0.0059848].

The [canonical PIQA result](../donor_adaptation/probes/STRAT_01_GIGACHAT31_PIQA_RESULT_20260920.md)
binds scorer, runtime, tokenizer, source data, token IDs, manifests, and raw
score hashes. This is a measured task result, not an inference from BPB.

## Decision and remaining gates

The preregistered stop rule now authorizes exactly the frozen 96-document
greedy rollout. That is the next quality step. HumanEval functional scoring
remains `PENDING_SANDBOX`; generated code must not be executed on the Windows
host.

The rollout apparatus has since passed its frozen preflight: no-model tests,
real source-token binding for all 96 documents, and a paired one-document
BF16/Q4 smoke are valid. Each arm generated exactly the same trajectory at
batch 128 and batch 64, and neither arm triggered `run32`, `loop8x3`, or
`empty`. This authorizes the full paired arms but is not itself the
96-document rollout result; see the [execution brief](../donor_adaptation/briefs/BRIEF_STRAT_01_GIGACHAT31_DOCUMENT_ROLLOUT.md).

The result does **not** qualify the final goal. The accepted artifact still
needs document rollout, semantic/token parity in the actual extended
`benchmarks/phase60/engine.c` path, and an end-to-end accepted-token rate with
lower CI95 at or above 50 tok/s. The MTP pilot remains a separate base-plus-
draft artifact with unresolved equivalence and inadequate observed rate.

No T4 session was used for this PIQA gate.
