# C50-A8 result: Ling-mini-2.0 chats in C (tokenizer, template, loop)

17 October 2026. Under the [A8 protocol](C50_A8_CHAT_DELIVERABLE_PROTOCOL_20261017.md). A8 is
a deliverable, not a gate. The verification rule was fixed before any check ran.

## What exists

| File | Role |
| --- | --- |
| `benchmarks/chatbot50/c50_tok.h` | The source tokenizer in C, with its data read from the GGUF: added tokens, NFC, the Split regex matched by hand, byte-level BPE, and a lossy-UTF-8 decode. |
| `c50_unicode_tables.h` | Unicode 15.0.0 classes and NFC data, generated by `c50_a8_gen_unicode.py`. |
| `c50_chat_template.h` | The chat template: system, user and assistant, thinking off, no tools. |
| `c50_chat.c` → `bin/c50_chat.exe` | The interactive loop on the unchanged A3 engine: greedy or temperature/top-p, `/reset`, `/exit`, and a batch mode. |

**How to run it:**

```
benchmarks/chatbot50/bin/c50_chat.exe --model E:/SiliconLLM_Artifacts/campaigns/chatbot50_20261016/gguf/ling-mini-2.0-a810f64-q4_k_m.gguf [--system "..."] [--temp 0.7 --top-p 0.9 --seed 1]
```

Build: `clang -O2 -mavx2 -mfma -mf16c -Wno-unused-function -o bin/c50_chat.exe c50_chat.c`.

**Verdict: PASS on the first attempt.**
- **Regression check.** `c50_token_raw` was then factored out of decode for streaming, and

**Planted controls.** These were added after the pass and are outside the gate
(`results/c50_a8_verify_plant_*.json`). Three builds each carry one known defect, and each
defect is caught:

| Defect | Caught by |
| --- | --- |
| NFC skipped | T3: 1,046 mismatches, all 500 nfc strings among them. **T1 and T2: 0.** |
| `\s+(?!\S)` alternative removed | T1: 123, T3: 280, T5 IDs: 2 |
| one U+FFFD per invalid byte | T4: 327 |

The first row is a measured fact about the sets:
- FIT texts are NFC-stable by construction (`c50_holdout.py` skips NFC-unstable spans).
- So a tokenizer without NFC would pass every document panel of this programme. Only the
  stress set sees the defect.

## T6 loop smoke (`results/c50_a8_t6.json`)

Batch mode, greedy, 64 new tokens, on the P0 GGUF:

| Prompt | Prompt tokens | Generated | Stop | Engine output (start) |
| --- | --- | --- | --- | --- |
| Qual è la capitale del Portogallo? Rispondi in una frase. | 36 | 11 | EOS | "La capitale del Portogallo è Lisbona." |
| Explain in two sentences why the sky is blue. | 28 | 52 | EOS | "The sky appears blue due to a phenomenon called Rayleigh scattering, …" |
| Write a Python function that returns the n-th Fibonacci number. | 30 | 64 | MAX | "Certainly! The Fibonacci sequence is …" |

**T6 passes:** the loop runs, stops at EOS or at the limit, and prints CONFIG.

**Reported against `c50_llama_generate` on the same GGUF and the same prompt IDs** (greedy, ties
to the lowest ID):
- prompts 1 and 3: identical token for token;
- prompt 2: diverges at generated token 42 of 52.

This fits the near-tie disagreement floor that A3 measured. It is a smoke, not a fidelity
claim.

## What this cannot say

- **No rate.** The loop prints wall seconds per turn, but the box was contended by the A4 run.
  Rates belong to A7.
- **No quality claim** beyond these three answers; quality is A4 and A7.
- **Prefill is token by token**, and every prompt token pays for the full head. That is
  correct but slow; it costs time to first token, not the decode rate. A7 records TTFT.
- **Scope:** Unicode 15.0 data; no tools, and no thinking mode.
