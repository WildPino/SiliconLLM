# C50-T1 protocol, part 1: does S4's LoRA survive a merge into T0's own 4-bit file? (MVE-0)

24 October 2026. Registered before any merge is built or scored. The cell follows the decision of 24 October (ROADMAP
§12, option C, `c97e3e9`): after S4's FAIL ([result](C50_S4_RESULT_20261023.md)), make a "T1", meaning T0 improved
by distillation with **no byte added**, so that it runs at v0.

The cell has two parts.
- **Part 1, this document: MVE-0.** It runs locally on the CPU, with no T4 and no new training. It asks whether the
  trained LoRA c48 from S4 keeps its gain once it is merged into a Q4_K_M file built exactly like P0.
- **Part 2: the regression fix** (nq, tqa) on T4. It gets its own protocol, pushed before any T4 session, and its
  design depends on this part's outcome.

## Question

S4's control c48 recovered R = 0.699 of the T0 → F0 document gap. That number comes from the PyTorch instrument, on
T0's dequantized weights plus an unmerged rank-48 LoRA, run in fp16. The engine runs one Q4_K_M file. Three questions
follow:

1. Does `Q4_K_M(BF16 + ΔW)`, built with P0's recipe, keep the gain?
2. Is its byte layout identical to P0's, so that v0 holds by construction?
3. What does it do to the general panel, measured in the llama.cpp instrument that defined S2's gap?

## What is merged

- **The LoRA:** c48's `final.pt` from `sirwildpino/c50-s4-train-c48-s2`, the same file S4's evaluation mounted; its
  sha256 is recorded.
- **ΔW = B · A** (fp32, shape [n_out, n_in]) for the 100 tensors the LoRA covers:
  - layer 0: `attn_qkv`, `attn_output`, `ffn_gate`, `ffn_up`, `ffn_down`;
  - layers 1-19: `attn_qkv`, `attn_output`, `ffn_gate_shexp`, `ffn_up_shexp`, `ffn_down_shexp`.
- **The merge:** a copy of T0's BF16 GGUF (`ling-mini-2.0-a810f64-bf16.gguf`) where only those tensors' bytes are
  overwritten with `bf16(W + ΔW)`, computed as `W` in fp32 plus ΔW, then rounded to nearest-even. Every other byte of
  the file is untouched.
- **The quantization:** P0's recipe, unchanged:
  - `llama-quantize --imatrix ling-mini-2.0-a810f64-imatrix-fit24.gguf <bf16> <out> Q4_K_M 6`;
  - pinned build `llama.cpp-5b335f4`.
- **Note on the base:** the LoRA was trained on top of P0's dequantized weights, not on BF16. Merging into BF16 and
  re-quantizing is the route that leaves every untouched tensor identical to P0. The quantization error the LoRA had
  learned around is replaced by a new one, and the measurement below includes that.

## Checks before any score (each must pass; a failure stops the cell for a design review)

| Check | Rule |
| --- | --- |
| **K0, P0 reproducible** | quantizing the **unpatched** BF16 with the recipe above gives a file whose sha256 equals P0's pin `44de7315…`. If the AVX2 build does not reproduce it, the generic build of the same commit is tried once, and the build that reproduces it is the one used |
| **K1, patcher identity** | the patcher run with ΔW = 0 writes a file whose sha256 equals the BF16 original |
| **L's planted controls** (before L is read on T1) | `layout` of P0 against itself passes with 0 differing tensors; `layout` of P0 against M0 (Q4_K_M without imatrix, pinned in S2) fails, because tensors outside the LoRA differ |
| **L, layout** | T1 has P0's 278 tensors with the same names, types, shapes and byte counts, and the same file size. Only the 100 merged tensors may differ in their data; every other tensor's data is byte-identical to P0's |

**Also reported, not gated:**
- per merged tensor, the share of ΔW that survives BF16 rounding, ‖bf16(W + ΔW) − W‖ / ‖ΔW‖, and the cosine
  between bf16(W + ΔW) − W and ΔW;
- the same two numbers after Q4_K_M, against P0's dequantized tensor.

## Scoring (llama.cpp, the S2 and A4 instrument)

- **What runs:** T1 through S2's seven panels (docs, nq, tqa, mmlu, arc, gsm8k, chat), with the pinned executables
  and settings of `c50_s2_run.py`: 6 threads, ubatch 512, flash attention off, S2's stop tokens, and each CONFIG line
  asserted.
- **The reference** is S2's T0, which is A4's P0 outputs plus S2's T0 panels: the same files as the S4 verdict's
  denominator.

**Gate M, the merge keeps the gain.** On the 36 S4 documents:
- **R_llama(T1) = (bits_T0 − bits_T1) / (bits_T0 − bits_F0)**, all three from llama.cpp, with its CI95 from 10,000
  paired document-bootstrap draws (seed 20261016).
- **PASS iff R_llama(T1) ≥ 0.80 × R_pt(c48) = 0.559.** The margin of 0.140 is larger than the instruments'
  disagreement measured in MVE-5. There, PyTorch T0 against llama.cpp T0 differed by ≤ 0.010 BPB, which is 0.041 of
  the 0.244 BPB gap.

**Also reported, not gated:**
- T1 against T0 on each general panel (nq, tqa, mmlu, arc, gsm8k, chat) and on the 206 donor-gap items, by A4's
  paired rule;
- the same comparisons for c48 in PyTorch, from S4's post-hoc record, side by side.

The nq and tqa regression is part 2's target, not this gate.

**Speed.** If L passes, T1 has P0's bytes per token, and S1's law makes v0 hold by construction. The claim stays
"by layout" until a timed S0 session runs on T1. That session reads times, so it needs an empty machine and the
user's go (rule 7); it is requested separately and is not part of this gate.

## Outcomes

- **MVE-0 PASS** (K0, K1, L, M): T1-c48 is a valid artifact at v0's layout, and part 2 trains with merge as the final
  step.
- **MVE-0 FAIL on M:** the merge loses the gain. Part 2's design must then train against the quantized grid, or
  quantize after training and recover. This calls for a design review, not a retry.
- **K0, K1 or L fails:** the tool is wrong. The cell stops for a review.

## Budget and order

All of it is local and on the CPU, quality only, with no timed rate. It is launched without asking, one long job at
a time.

1. **Download** c48's `final.pt` (~70 MB) and record its sha256.
2. **Patcher:** K1, then the merge. This takes a 32.5 GB copy on E:.
3. **K0:** quantize the unpatched BF16 (~15-30 min).
4. **Build T1:** quantize the merged BF16, then check L.
5. **Seven panels:** ~2.7 h, from M0's walls in S2.
6. **Verdict:** `c50_t1_verdict.py mve0`, which reads only the records.

**Tools,** pushed with this protocol:
- `c50_t1_merge.py`, with `merge` (also `--zero` for K1), `quantize` and `layout`;
- `c50_t1_run.py`, S2's panels for one model;
- `c50_t1_verdict.py`.

The patcher passed a smoke test on a synthetic BF16 GGUF:
- the merged tensor equals bf16(W + BA), and the other tensor is untouched;
- `--zero` writes back an identical file.

**Disk:** about 52 GB on E:, which has 4.4 TB free.

## What this cannot say

- One LoRA (c48), one seed, one merge route.
- The 36 documents and 206 items are S4's. A PASS says that the gain survives the merge. It does not say that T1 is
  a better chatbot.


## Addendum 1 (24 October, after MVE-0 PASS, before any run of it): part 2a, where the gain and the loss live

MVE-0 passed ([result](C50_T1_MVE0_RESULT_20261024.md)), so merging is a validated last step. Part 2a is a
diagnosis on the CPU that needs no T4 and no new training. It runs before part 2's T4 protocol, because its
outcome chooses that protocol's first arm.

**What runs.** Two partial merges of the same c48 LoRA, each with MVE-0's patcher, recipe and checks:
- **attn:** only ΔW of `attn_qkv` and `attn_output`, all 20 layers (40 tensors, 54.5% of ‖ΔW‖²);
- **ffn:** only ΔW of the shared expert (layers 1-19) and of layer 0's dense FFN (60 tensors).

Each partial T1 is quantized with P0's recipe and checked with `layout --only <group>`: only that group's tensors
may differ from P0. Then it is scored with `c50_t1_run.py --panels nq,tqa,docs`, the same executables and settings
as before.

**Read by `c50_t1_verdict.py part2a`.** For each variant:
- R_llama on S4's 36 documents, with its CI95;
- nq and tqa against T0, by A4's paired rule.

The reader was checked first on the full T1, fed as a variant: it gives MVE-0's numbers exactly (R 0.6970; nq
b 33, c 13; tqa b 30, c 15).

**Decision rule for part 2's first T4 arm, fixed now.** A variant is *clean* iff it keeps the gain
(R ≥ 0.559, MVE-0's threshold) **and** is not worse than T0 on both nq and tqa.
- If a group is clean, part 2's first arm trains the LoRA on that group alone.
- If no group is clean, part 2's first arm is the anchored LoRA: all of c48's modules, with the loss anchored to
  T0 where T0 is confident.

Nothing here is a gate on T1. A partial merge of a LoRA trained jointly is not the same as training that part
alone; this only says where the effect sits in c48.

**Registered predictions.**

| Prediction | Value |
| --- | --- |
| L for both variants | passes, with exactly 40 (attn) or 60 (ffn) tensors differing |
| R_llama | attn 0.35-0.55, ffn 0.25-0.45, both below the full 0.697 |
| nq and tqa | the regression sits mostly in the FFN part: ffn regresses on both; attn is not worse on at least one of them |
| Decision | no group is clean (the gain needs both parts), so part 2 starts with the anchored arm |

**Budget:** two local chains (patch, quantize, layout, three panels), about 2 h each, one at a time, quality only.
