# Large-family admission before selecting another small pilot

15 October 2026. This is a decision screen, not a new donor or performance result.
It applies the corrected scope: one suitable native conditional family can
satisfy the goal, but a small member's success does not establish large-scale
useful capacity and speed.

## Separate the reducible and protected costs

For each intended large family member, report the original learned capacity,
packed resident pool and the complete active ledger at declared contexts.
Separate routed expert coefficients from shared experts, attention/recurrent
projections, vocabulary scoring, router IDs/masses and state/KV. Identify a
specific transformation for every exceeded allowance. Further splitting experts
is a plausible conditional-computation variable, but does not reduce unrelated
always-on matrices by itself.

The [independent review](INDEPENDENT_REVIEW.md) derives a strong local warning
from [M397](../NATIVE_EXPERT_SCALING_20260925/METH_397_QWEN_NEXT_SOURCE_HEADERS_RESULT_20261004.md):
Qwen3-Next80B retains about2.054B non-routed active positions even if all routed
experts are omitted. Thus that large source is not admitted by a successful
small Granite expert-only kernel. This is a source-specific screening argument,
not a rejection of native MoE or of all transformations of that model.

## Broader native conditional memory is relevant, but not a ready checkpoint

[UltraMemV2](https://arxiv.org/html/2508.18756v1), section4.1, reports a120B
memory-model configuration with2.5B activated parameters. Its large comparison
is proprietary, and the report finds that denser retrieval from60B can beat
sparser retrieval from120B. This supports distinguishing useful consultation
from total stored size. It is not a demonstrated pretrained-to-this-engine
conversion. The [official implementation](https://github.com/ZihaoHuang-notabot/Ultra-Sparse-Memory-Network)
provides training code and a227M-active/1.2B example; that is not verification
of an available120B instruction donor, source weights or local CPU50.

[Engram](https://arxiv.org/html/2601.07372v1) studies deterministic conditional
lookup as an additional memory axis. Its [official repository](https://github.com/deepseek-ai/Engram)
is relevant implementation material. This is architectural evidence to inspect,
not evidence that an existing dense or MoE donor can be transferred into those
tables cheaply while preserving its knowledge. Source capacity, learned
backbone and conversion cost must remain explicit.

Neither paper is a reason to begin pretraining or to count a large lookup table
as the requested capacity result. Before choosing such a path, establish an
accessible pretrained instruction checkpoint, its actual core and memory
values, reproducible reference semantics and a bounded conversion procedure.
Do not substitute training code, a published parameter count or accelerator
speed for those prerequisites.

## Next numerical work

Close the already completed Falcon source capture and its independent adoption
audit as reusable data. Do not continue its narrow replay automatically. Before
another substantial model-value acquisition or learner, freeze one candidate
family's large-member active-cost plan and the small pilot's exact decision
value. A complete packed-kernel screen can be an enabling first experiment;
it must not be described as large-model quality or a solution to its core cost.
If the intended large member still lacks a credible core transformation, retain
that open issue in the method rather than concealing it behind pilot speed.
