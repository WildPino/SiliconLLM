# Offline first-attention acquisition closure audit

`benchmarks/native_expert_scaling/first_attention_acquisition_audit.py` is a standard-library-only, CPU-only audit of the **completed** `results/native_expert_scaling/first_attention_source_repair3_20261015` acquisition. It must run only after that directory has a successful `terminal.json`. It never downloads source data, loads a tokenizer or model, generates cases, or runs a quality or speed benchmark. Run it with an exact committed `--freeze` revision after reviewing this script and protocol; its exclusive default output is `results/native_expert_scaling/first_attention_source_audit_20261015`.

The auditor verifies source terminal success and PID/create-time linkage to the owned-process receipt; the terminal's manifest digest; complete input-pin, tokenizer, tensor, and embedding-row file seals before and after audit; exact source directory inventory; and the 512 MiB output cap. It independently recomputes the source-family selection and exclusions from the sealed corpus and original source plan. The corpus scanner lexically skips stored answers, output IDs, and logits; it decodes only public input and provenance fields. The auditor then checks the saved eligibility/selection plans, exact 24 FIT/12 DEV cases, eight FIT and four DEV domains with no overlap, 36 distinct IDs/group/first-user keys, original public messages and prefix provenance, canonical and first-256 U32-LE token ID hashes, the 62-token common prefix and positive variable-query suffix in every case. It checks exactly 1,501 sorted used embedding IDs, their row lookup, the BF16 `[1501,2880]` payload length/hash, and all ten exact layer-0 tensor names/shapes/BF16 lengths/hashes.

The HTTP journal must exactly match the manifest's event copy. Each recorded successful range must have 206, exact `Content-Range`/length, bounded span, and ETag consistency with the source descriptor when present; refused requests must show no body read. The auditor reconciles recorded calls and body bytes with the 16 MiB metadata, 64 MiB tokenizer, 256 MiB weight, 384 MiB network, 2,048-call, 2 MiB span, and 100 MiB coalesced-gap caps. It independently hashes each retained complete tensor chunk against its recorded range-response hash. It verifies embedding span offsets, sizes, and row-plan coverage against the journal and exported row file hash.

The auditor independently recomputes the response hash for each embedding span made entirely of retained rows, and reports the count and bytes replayed. The saved raw safetensors header bytes and unused gap bytes from other coalesced embedding responses are unavailable. Their original response hashes and header keyset/contiguity checks remain producer witnesses, not independently replayable source-byte checks. The audit reports the number and bytes of such spans separately. It does not establish remote authenticity, numerical quality, semantic behavior, transfer, or accepted-token rate.

Earlier failed preflights remain separate: `first_attention_source_20261015` failed the runtime-location assertion; `first_attention_source_repair1_20261015` failed an incorrect tokenizer-length equality; `first_attention_source_repair2_20261015` failed a tokenizer return-type assertion. Their failed terminal receipts are hashed and summarized in the audit; only repair3 is a candidate for PASS. The auditor does not repair, merge, or silently substitute any of those attempts.
