# First-attention source-group contribution oracle

**Status:** prepared CPU-only source-contribution falsifier. It consumes the pinned GPT-OSS-120B first-block acquisition, the sealed `first_attention_rank_20261015` source BF16 and full-F32 traces, and the independent CPU numerical audit. It does not rerun the producer, train, fetch data, import model code, or call CUDA. The preserved producer status is `FAILED_GPU_RELEASE`; the independent numerical audit concluded `RANK256_F32_REJECT`. Neither status is changed by this oracle.

## Fixed representation and decision

The 64 source query heads are partitioned into **16 contiguous groups of four heads**. Each group spans exactly 256 O-input columns, aligned with a Q4_K block. Authentic source matrices are retained. For every token, compute the source F32 V projection from the genuine BF16 embedding row and input RMS norm, then combine it with the **saved full-F32 source probability trace** over the legal causal window of 128 keys. The sink is the last probability category and contributes no V vector. Each group's contribution is `h_g = W_O[:,256g:256(g+1)] @ context_g`; source O bias is added once to the reconstructed full branch and once to a selected-group branch.

The target is the official saved BF16 pre-residual branch minus the source O bias. For **every** token and all 16 groups, the primary oracle chooses any finite signed real mass by the analytic minimum `a_g = dot(h_g,target)/dot(h_g,h_g)`, or zero when `h_g` has zero norm. It chooses the group with the lowest F64 residual, ties resolved by lowest group ID. This unbounded signed-real class contains nonnegative, clipped, or normalized-mass choices, so a failure is not caused by an arbitrary mass cap. Negative masses, `|a|>2`, absolute magnitude and group counts are reported for all tokens and for variable-query tokens. A predeclared `[0,2]` clipped-mass oracle is reported only as a diagnostic and cannot replace the primary decision. Selection uses the true target on DEV, so this is a representational lower bound, **not** a learned selector or held-out deployable quality result.

All 36 original cases are fixed: 24 FIT, 12 DEV, with the already sealed `common_prefix_length=62`. The primary branch gates use only queries at positions at least 62. There is no new budget grid, optimization, data selection, or DEV-based design choice. First, the sum of all 16 reconstructed groups plus one O bias must match each saved full-F32 source branch at all-token relative L2 `≤3e-4`. On each split, the reconstructed all-group branch must also meet pooled relative L2 `≤.01` and nearest-rank per-sequence p95 `≤.05` against the saved official BF16 branch. If either control fails, status is `INCONCLUSIVE_CONTROL`. Only then do the same two branch gates adjudicate the unbounded one-group oracle on FIT and DEV. A failure is `ONE_GROUP_ORACLE_LOWER_BOUND_FAIL` for this representation; a pass is `ONE_GROUP_ORACLE_LOWER_BOUND_PASS` and permits a later ID/mass predictability question only. Neither result admits a whole model, CPU timing, chat quality, physical Q4 format or selection mechanism. No TV gate applies because the represented output omits 60 source query heads; this is a new branch-function test, not a relaxation of the earlier rank-256 protocol.

The oracle saves one `.pt` record per case: source case identity and IDs, selected group IDs, F64 selected masses, all 16 analytic squared residuals, and F64 one-group/all-group branch traces. The result contains FIT/DEV metrics, all-token diagnostics, source-group and mass statistics, case records, input binding hash, old numerical-audit SHA, `producer_status=FAILED_GPU_RELEASE`, and `admitted=false`. These traces permit independent recomputation of the reported metrics and selected-group residuals using the frozen inputs.

## Freeze and execution boundary

The `--freeze` step hashes its own code/protocol, manifest, producer result, numerical audit, source config/reference, the required source BF16 norm/V/O tensors and embedding rows, 72 source/F32 trace files, plus the CPU runtime modules. It verifies each source descriptor and producer trace-owned SHA and writes an exclusive binding. The `--run` step requires the same hashes before numerical work and rechecks them afterward. Use explicit paths; the directory names below identify the currently sealed inputs:

```powershell
python benchmarks/native_expert_scaling/first_attention_source_group_oracle.py --manifest results/native_expert_scaling/first_attention_source_repair3_20261015/manifest.json --producer results/native_expert_scaling/first_attention_rank_20261015 --numerical-audit results/native_expert_scaling/first_attention_cpu_audit_20261015.json --freeze results/native_expert_scaling/first_attention_source_group_oracle_binding_20261015.json
python benchmarks/native_expert_scaling/first_attention_source_group_oracle.py --manifest results/native_expert_scaling/first_attention_source_repair3_20261015/manifest.json --producer results/native_expert_scaling/first_attention_rank_20261015 --numerical-audit results/native_expert_scaling/first_attention_cpu_audit_20261015.json --binding results/native_expert_scaling/first_attention_source_group_oracle_binding_20261015.json --run --output results/native_expert_scaling/first_attention_source_group_oracle_20261015
```

No command has been launched by this preparation. The output directory must not exist. It receives exclusive `owned_process.json`, `result.json` and `terminal.json` receipts with PID/create time, file hashes and outcome, plus the 36 per-case traces. Six CPU threads and empty CUDA visibility are set before importing PyTorch. The in-process guard checks a ten-minute wall, 3-GiB RSS/peak working set and 512-MiB output cap before and after each case; a single blocking CPU kernel can overrun before the next check. Resource estimates are roughly 3–8 minutes, under 3 GiB RSS and under 512 MiB output on the current six-core host; these are estimates, not measurements.

Runtime seals also include `torch_cpu.dll`, `torch_python.dll` and `c10.dll`.
For every token/group, direct squared residuals at the analytic optimum are
checked against the quadratic identity within `1e-11 * max(target_norm2,1e-30)`.
The primary argmin uses the directly evaluated residual, avoiding cancellation
in the quadratic formula. Both forms are retained in the case record.
